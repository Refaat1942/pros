1. Purpose of This Document

This architecture document describes how the system is built and deployed: server topology, software layers, database design, security controls, and operational procedures. It complements the System Blueprint (business view) and is intended for IT staff, vendors, and technical auditors.

4. Layered Architecture

┌─────────────────────────────────────────────────────────┐ │ PRESENTATION — Blade views + role dashboards (Chrome) │ ├─────────────────────────────────────────────────────────┤ │ HTTP — Routes → Controllers (thin — views/JSON only) │ ├─────────────────────────────────────────────────────────┤ │ DOMAIN — Services (~90 classes) — ALL business logic │ ├─────────────────────────────────────────────────────────┤ │ DATA — Eloquent Models + PostgreSQL/MySQL │ ├─────────────────────────────────────────────────────────┤ │ CROSS-CUTTING — AuditService, WorkflowService, Events │ └─────────────────────────────────────────────────────────┘

Non-negotiable rule

Controllers return views or JSON. All business rules live in Services. Workflow stage changes happen only through WorkflowService triggered by domain events — never by ad-hoc controller updates.

5. Request Flow Example

Browser POST /technical/bom/scan-dispense → Route (routes/web/technical.php) → BomController::scanDispense() → BomService + BarcodeValidationService → WorkflowService (BomDispensed event) → AuditService::log() → StockMovement + CaseRecord updated in DB → JSON response to browser

14. WAC Recalculation (Moving Average)

StockPriceService.recalcWac() new_wac = (prior_qty × prior_wac + in_qty × in_price) / (prior_qty + in_qty) Triggered by: • StockReceiveService (physical inward) • StockPriceService.addBatch() (price batch registration) NOT used for civilian quote line pricing — only for inventory value & profit cost.

15. Stock Deduction on Sale / Dispense

There is no separate “sales module” that manually adjusts stock. Dispense IS the stock deduction — tied to a validated work order:

  1. BomService.refreshUnitCostsAtDispense() — current WAC stamped on every BOM line
  2. BomService validates scan against BomItem line
  3. stock_items.qty decremented; reserved released if applicable
  4. StockMovement created (type issue, unit_cost = WAC, BOM reference, balance_after)
  5. cases.issue_cost snapshot stored (Σ qty × WAC)
  6. WorkflowService fires BomDispensed event
  7. FinancialPostingService.postOnDispense() — civilian contract debt (atomic ledger_posted_at)
Mismatch scan → BarcodeDispenseMismatchException → transaction blocked → audit entry. Stock and finance stay aligned.

18. Profit Margin Calculation

At barcode dispense (BomService.releaseToWip): • refreshUnitCostsAtDispense() → all BOM lines use current WAC • StockMovement.unit_cost = WAC • cases.issue_cost = Σ(qty × WAC) ← snapshot for finance ProfitabilityReportService (delivered cases): revenue = quote_total (civilian) | military_selling_price (military) cost = issue_cost if set, else internal_cost (WAC estimate at costing) margin = revenue − cost margin_pct = margin / revenue × 100 ItemPricingAnalyticsService (catalog): unit_margin = highest_purchase_price − WAC margin_pct = unit_margin / WAC × 100

19. Accounting Period Model

AccountingPeriod + PeriodOpeningOverride allow finance to set manual opening balances at period start (e.g. fiscal year alignment). FinancialBalanceService.balancesForPeriod() applies overrides when generating opening/closing reports.

12. WorkflowService — Single Authority

19. Update Procedure (Offline)

  1. Run backup: php artisan prosthetics:backup
  2. Pull code: git pull (or copy from USB if no internet)
  3. Dependencies: composer install --no-dev --optimize-autoloader
  4. Schema: php artisan migrate --force
  5. Cache: php artisan config:cache && route:cache && view:cache
  6. Staff refresh browser: Ctrl+F5

Never overwrite .env or storage/ during updates.

24. Scalability & Limits

  • Designed for: Single center, one LAN, tens of concurrent browser sessions
  • Not designed for: Multi-site cloud SaaS, public internet exposure, mobile native apps
  • Horizontal scaling: Not applicable — single-server offline model
  • Performance: Route/config/view caching enabled in production; OPcache recommended on PHP
